== DONE — VPN TOGGLE (shipped, wired, verified live) ==
Which services run inside gluetun is now a runtime operator choice, not hardwired.

  Model: a service opts in with label mediastack.vpntoggle="true". vpn_gen reads its metadata and
  writes local/vpn-overlay.yml (gitignored, loaded by DC after the user override, before pins). The
  overlay is ADDITIVE (no compose !reset), deterministic (sorted), regenerated on `up` and on any `vpn`
  change. Toggle fragments therefore carry NO network_mode / networks / ports / traefik-router labels —
  only metadata: mediastack.{port, subdomain, vpn(=default), hostport(optional)}.

  Override: <SVC>_VPN=true|false in .env is the per-deployment source of truth. `vpn <svc> on|off`
  writes it ONLY when it differs from the fragment default, and CLEARS it (env_del) when it matches —
  so a redundant override self-heals and the listing shows no stray entry.

  Defaults (recommended): IN = qbittorrent, deluge, transmission, sonarr, sonarr-anime, radarr,
  radarr-4k, lidarr, prowlarr, bazarr, lazylibrarian, apprise. OUT = audiobookshelf + all serving/infra.

  Guardrail: torrent clients (qbittorrent, deluge, transmission) refuse `vpn <svc> off` without --i-know.

  Pinned STATIC, never toggleable (moving them out breaks their consumer):
    - flaresolverr — Prowlarr reaches it inside the namespace (localhost). Static network_mode; the sole
      remaining per-service entry in gluetun.yml (its port + the 6881 BT ports).
    - recyclarr    — one-shot trash-sync tool, unmanaged (no mediastack.managed), reaches the arrs on
      localhost; VPN'd by fragment, excluded from audits by design.

  Option A applied: deluge + transmission GAINED real Traefik routes (were port-only before) — WebUIs
  now reachable like qBittorrent's.

  hostport label: mediastack.hostport="false" => traefik-only, no host port published in either state
  (for serving apps whose container port collides on the host — audiobookshelf is :80 vs Traefik).
  Default "true" preserves direct host access for the acquisition apps. audiobookshelf is the first
  serving-side toggle service (default OUT; only egress is public podcast feeds, so VPN optional).

  Two views (intentionally redundant — Nick's call, both informational):
    - ./mediastack.sh vpn         preamble + SERVICE / VPN / RECOMMENDED, on/off, flags changed rows.
    - ./mediastack.sh status      VPN column = on/off, `self` for gluetun, `*` = changed-from-recommended,
      plus a footnote legend.

  Verified live on anzac3 across every wave: leak-test green in both directions, guardrail refuses,
  audiobookshelf toggles IN with NO :80 host collision and keeps resolving, deluge/transmission routes
  return 200/301. NOTE: vpn_gen has NO /tmp/h4 harness coverage — proven via ad-hoc emit-tests + anzac3.

  Audit done this session: no OTHER non-VPN service needs the tunnel. Serving apps make only benign
  metadata calls or serve local media; audiobookshelf (podcasts) added as the one optional lever.
